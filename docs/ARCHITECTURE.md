# 架构说明

LightSail Panel 由 React 前端与同源 Node.js 24 API 组成。服务端负责认证、输入校验、AWS 请求、凭证加密和数据持久化。

## 请求路径

`server/app.mjs` 在业务路由前执行来源校验、会话认证和 CSRF 校验。读取与修改资源的参数通过 Zod 校验后交给 `AwsGateway`。资源操作调用官方 Lightsail API，账户添加使用 STS 查询身份。

账户凭证仅在服务端解密，账户列表仅返回元数据与密钥尾号。默认 SSH 私钥下载须通过会话、来源和 CSRF 校验，响应禁止缓存。

账户记录保存 SDK 身份验证端点区域，资源查询区域由前端独立选择。

页面入口在服务端校验登录 Cookie，将认证结果、账户元数据与已有资源快照嵌入不可执行的 JSON 数据块，响应禁止缓存。资源快照最多 512 条，序列化总量上限为 512 KiB，优先包含非空实例、区域与套餐；创建目录和非月度流量仅在对应页面提供。操作日志页面同时读取本地日志。此过程不触发 AWS 查询。

前端在首次渲染前初始化会话与资源缓存，并规范化查询参数及静态 IP 的账户、区域信息。流量仅恢复浏览器时区匹配的当前统计周期。未登录时显示登录或初始化表单；JSON 转义 HTML 分隔字符，不包含账户凭证、SSH 私钥或会话 Cookie。开发服务器缺少入口数据时，通过认证接口校验，并在当前面板框架内显示连接错误。

## SSH 终端

AWS 返回的 `expiresAt` 可选；存在时预检到期时间，证书有效期由 OpenSSH 在认证阶段校验。

实例操作菜单动态加载 xterm.js 与 FitAddon。终端测量容器独立于外层边框和内边距；ResizeObserver 同步终端与服务端 PTY 尺寸。全屏切换保留终端实例、输出和 WebSocket 连接。Escape、Tab、Ctrl+C 由终端处理；关闭窗口结束连接，断线保留输出，重连建立新会话。

历史滚动统一由 xterm 滚动组件处理，背景层禁用原生滚动。终端容器在捕获阶段拦截 `Ctrl+Shift+C` 并复制选中文本；无选区时保留剪贴板。

`POST /api/ssh/connect` 经会话、来源与 CSRF 校验后签发单次票据，绑定当前会话，有效期 45 秒。`/api/ssh/terminal` 校验 WebSocket 来源与登录 Cookie，票据通过第一帧提交并立即消费。连接与待用票据合计上限为每会话 4 个、全局 16 个。

`server/ssh/sessions.mjs` 确认实例运行后调用 `GetInstanceAccessDetails`，通过 `server/ssh/openssh.mjs` 启动 OpenSSH 和 node-pty。临时私钥、证书与 AWS 主机密钥记录写入受限临时目录，使用证书认证与严格主机密钥校验，禁用密码、代理、端口转发及用户 SSH 配置。子进程只继承运行所需的系统变量，不继承 AWS 或面板密钥。PTY 提供终端控制字符及远程窗口尺寸同步，登录 shell 发出就绪标记后才允许输入。

WebSocket 每 15 秒检查心跳、登录有效期和账户状态；退出登录立即撤销连接。超时、断线、关闭窗口或停止服务时结束 PTY 并清理临时文件。审计仅记录连接目标与结果，票据、终端输入输出和临时密钥不持久化。SSH 会话独立于资源缓存。Docker 构建阶段编译 node-pty，运行镜像内置 OpenSSH；反向代理须支持 WebSocket。

## 缓存与并发

`server/resource-snapshots.mjs` 按规范化路径、账户、区域和查询参数管理快照，将成功结果、采集时间与过期时间保存至 SQLite 的 `resource_snapshots` 表，最多保留 5000 条。普通读取优先返回已有结果，过期时异步更新；同一查询合并在途任务。失败与部分失败不覆盖最近成功快照，重试对齐下一个 5 分钟时间点。手动刷新等待实际查询结果。

启动入口开启后台采集。实例、静态 IP 和本月流量按 `shared/refresh-policy.ts` 的 5 分钟边界更新；区域目录每 15 分钟、套餐目录每小时更新。采集优先处理账户默认区域及已有实例的区域，再扫描其他区域；任务并发上限为 4，交互查询优先于排队的后台任务。已请求的流量范围、时区和资源详情随后台周期更新。

区域发现尚未结束时，后续采集周期仍检查已有快照的期限，优先调度已有实例和流量；在途请求保持合并。AWS HTTP 连接超时为 5 秒，单次请求超时为 25 秒并中止连接，SDK 最多尝试 3 次，避免超时请求长期占用采集槽位。

前端跨页面共享资源缓存与在途请求，账户和区域扫描并发上限为 4。查询期间保留快照及行顺序，响应后原位更新；资源变更标记快照过期。连接失败保留上次结果，错误合并为可关闭提示，查询恢复后清除。

资源页手动刷新通过 `refresh=1` 跳过有效缓存；浏览器 F5 不携带该参数，继续优先读取服务端快照。操作日志由事件通知实时更新，不设置独立刷新按钮；读取失败时保留重试入口。

移动端导航由 `useMobileNavigation` 管理焦点循环、Esc 关闭、背景滚动锁定与关闭后的焦点恢复；背景工作区通过 `inert` 隔离，切换至桌面断点时解除导航状态。共享 `Select` 根据视口剩余空间定位选项列表，不主动滚动页面。

前端视觉变量和响应式约束见 [界面规范](UI.md)。控件边框与表面分隔线分别定义，焦点标记适应滚动容器；实例菜单的键盘导航同步滚动活动项。账户、自动关机与防火墙弹窗按内容确定高度，正文受视口约束滚动；SSH 保留独立的终端尺寸测量与全屏状态。

服务端采集不依赖浏览器可见性或登录会话。服务重启从 SQLite 恢复快照；首次采集尚未完成的查询等待实际响应。流量快照校验当前时区下的统计起点，跨日或跨月不复用上一周期数据。账户移除同步清理对应快照，已发出的旧请求不能恢复被移除账户的数据。

采集完成发布仅含查询标识的 SSE 通知，前端按账户、区域和资源类别合并通知，重新读取经认证的接口并原位更新。SSE 重连、页面恢复可见时重新校验浏览器缓存；事件流断开或超过 45 秒未收到心跳时，每 30 秒通过本地接口补查。补查复用服务端快照，不强制重新调用 AWS；页面自动查询仍在隐藏时暂停，不影响后台采集。

资源写操作按 `shared/resource-update.ts` 定义的账户、区域和资源类别使缓存失效。操作完成与异步状态变化通过应用级通知更新当前视图，其余缓存保持有效。

登录续期和自动关机规则保存不使资源缓存失效。规则检查与操作跟踪由服务端独立调度。

`server/launch-network.mjs` 将创建后网络配置与操作跟踪进度持久化至 SQLite。队列以 5–15 秒间隔和受限并发查询待完成操作，确认结果后结束，最长处理 10 分钟；新实例跟踪至运行状态。前端读取本地进度，页面刷新、切换或服务重启均复用任务记录。

资源写操作同时检查持久化待处理任务与进程内提交锁，阻止同一目标的并发请求。任务状态变更通过经认证的 `GET /api/events` SSE 连接通知前端，前端随后读取本地进度与对应资源；断线后自动重连，并保留轮询回退。完成提示显示 8 秒，失败提示保留错误详情并支持关闭。

`shared/firewall.ts` 将 AWS 协议编号规范化为 API 协议名称，统一创建、开放及状态确认的覆盖判断。协议、端口范围、IPv4、IPv6 与来源别名分别比较，CIDR 按网络地址及前缀匹配。已覆盖的开放请求不执行 AWS 写操作；关闭操作仅确认对应协议、范围与来源规则已移除，不将其他较宽规则误判为关闭失败。

## 界面布局

公共布局统一侧栏、顶部选择器及主内容区间距。主要操作置于页面标题右侧；实例概况集中显示数量与单一刷新时间，筛选控件紧邻列表。防火墙和流量页面使用紧凑实例选择器，不重复页面功能说明；费用、删除及网络中断提示保留在相关操作中。应用品牌与浏览器标题统一为 `LightSail Panel`。

`Field` 为非密码输入和文本域统一设置 `autocomplete="off"` 及密码管理器忽略标记；搜索、复选框、网络选项和 xterm 输入区使用相同策略。管理员密码保留 `current-password` / `new-password` 语义，不在页面或整个表单上禁用密码管理器。AWS Access Key 属于接口凭证，包含遮蔽显示的 Secret Access Key，均按手动输入字段处理。忽略标记参照 [1Password 开发文档](https://www.1password.dev/web/compatible-website-design)及 [Dashlane 表单文档](https://support.dashlane.com/hc/en-us/articles/4420122792594-Optimize-your-web-forms-for-Dashlane-autofill)，扩展是否遵循标记取决于其实现和设置。

入口背景在应用脚本执行前匹配当前主题，正常访问不显示独立加载卡片。已有快照同步用于首屏，尚未完成的查询使用无动态效果的静态占位；跨区域扫描全部结束后才判定空结果。防火墙与流量页面在实例发现和详情查询两阶段保持同一结构，创建目录的有效默认值在渲染时确定。首次界面与新增资源行采用 140 毫秒透明度过渡，遵循系统减少动态效果设置；刷新保留行节点，查询失败保留已有内容。脚本加载失败时保留重载入口。

公共 `Modal` 采用固定标题与滚动内容区，尺寸受视口约束。流量视图保持加载、空数据和查询结果的布局一致，切换统计范围时保留上一结果。独立页面的每日明细随页面滚动，弹窗内限制明细可视高度；移动端将资源表格转换为带字段标签的信息卡片，流量明细保留日期、入站、出站及合计值。创建目录加载状态复用现有控件。

创建页沿用主内容区宽度与边距。操作菜单统一图标尺寸、行高及文字起始位置，并进行中文字符的光学居中校正。`PendingButton` 在提交期间保持文案、尺寸与焦点，采用 160 毫秒透明度过渡，并通过 `aria-busy` 和状态播报反馈进度。提交期间阻止重复操作、锁定输入与弹窗关闭，保留错误内容至请求返回。刷新按钮采用相同禁用样式，焦点恢复使用 `preventScroll`。

## 流量计算

流量使用 `GetInstanceMetricData`，指标为 `NetworkIn` 和 `NetworkOut`，统计方式为 `Sum`，单位为 `Bytes`。查询范围从浏览器时区的日期零点开始，到最近完成的 5 分钟区间结束。历史按小时汇总，首尾不足一小时的部分按 5 分钟查询，时间窗口互不重叠。

`shared/traffic.mjs` 负责时间窗口、重复点去除与按日汇总。本月、近 7 天和近 30 天采用相同日期边界；缺失点和查询失败保持未知。数值仅在展示时格式化，流量保留两位小数。

流量展示统一使用 KB、MB、GB、TB，按 1024 换算；内部仍保存原始字节数，月额度与阈值计算保持一致。刷新及查询时间显示至分钟，审计事件时间保留秒。

实例列表仅显示一处刷新时间，取可见实例与流量查询时间的最早值，具体时间保留在悬停提示中；空区域仅参与完整扫描范围的时间计算。流量统计的页面与弹窗共用组件，仅显示一处统计范围及其时区，查询时间置于范围的悬停提示。`DailyTrafficChart` 复用按日快照，按日期顺序展示入站与出站合计；`dailyTrafficChart` 计算当前范围内的统一比例，缺失或无效值保留未知，不作为零流量展示。图表提示框根据鼠标位置定位，并限制在图表和视口的可见范围内；键盘与触控操作根据所选柱定位。图表支持点击和键盘方向键，移动端仅在图表内部横向滚动。每日明细默认展开，按日期倒序排列，不修改原始快照，也不增加 AWS 查询。切换范围时保留已有结果，待新结果返回后更新视图。流量更新时间表示查询完成时间，不表示 AWS 指标的最新采样时间。

`src/hooks/useInstanceUsage.ts` 通过独立的 `GET /api/bundles` 共享区域套餐与本月流量快照，按实例 `bundleId` 取得月额度。价格查询仅调用 `GetBundles`，不触发镜像与可用区查询。`TrafficProgress` 在列表和自动关机窗口展示用量、额度与比例。条形长度限制为 100%，百分比保留实际值；90% 和 100% 分别使用主题警示色与错误色，缺失数据标记为未知。

## 登录有效期与自动关机

登录有效期通过下拉框选择 12 小时、1 天、7 天、30 天或 90 天，默认 30 天；SQLite 会话过期时间与 HttpOnly Cookie 同步，续期只修改当前会话，不随普通请求自动延长。

`server/traffic-guard.mjs` 将实例阈值规则保存在 `traffic_limits` 表。规则默认关闭，阈值支持 0.1–100%，按区域套餐返回的流量额度与本月入站＋出站合计判断，月份使用规则保存的时区偏移。后台检查对齐每小时 00、05、10、15 分等时间点，最多两路并发；资源操作完成后立即检查对应实例，不依赖浏览器登录状态。规则绑定实例 ARN，替换同名实例须重新配置。

自动停止前再次确认实例状态和规则版本，持久化停止意图后提交操作；关闭或编辑规则会取消尚未提交的检查结果。权限失败暂停规则，数据不完整不停止；无法确认请求结果时不重复提交。停止请求通过资源队列跟踪实际状态并更新列表，结果写入操作日志。重启服务继续读取规则，下月不自动启动实例。

## 持久化

### 操作日志

`audit` 表保存操作标识、发起时间、目标、结果与执行详情，最多保留 5000 条；`GET /api/audit` 返回最近 200 条。`shared/audit-actions.ts` 集中定义中文显示名称及默认结果说明，AWS、SSH、IPv6、IP 等专业术语保留英文。`server/audit-details.mjs` 根据已确认的资源状态生成端口规则、绑定目标或实例状态详情；错误详情经过凭证脱敏，SSH 终端输入输出及私钥不写入日志。历史空详情在页面明确标注，不推断执行结果。

异步 AWS 写操作以 `submitted`（界面显示“处理中”）建立记录，资源队列持久化其 `auditId`，确认后将原记录更新为 `success` 或 `failed`。原操作名称、目标和发起时间保持不变，批量创建在同一条记录中汇总各实例结果；自动关机与 SSH 建连采用相同的状态更新机制。最终结果不可被迟到的处理中状态覆盖，已清理或因保留上限移除的记录不会重新创建。

日志写入、结果更新或清理后，Store 发布仅含事件类型的通知，经同源、会话认证的 SSE 连接使日志缓存失效；连接不传输凭证、资源详情或日志内容。连接关闭、会话撤销或 Store 关闭时移除订阅。反向代理须关闭事件流响应缓冲。

`DELETE /api/audit` 经会话、来源和 CSRF 校验后删除全部日志，并返回删除数量。清理仅作用于日志表及前端日志缓存，资源查询缓存保持有效。界面复用 `Modal` 和 `PendingButton` 进行确认与提交反馈；演示模式仅清理内存记录。

### 数据与加密

数据目录包含 `panel.sqlite` 与 `encryption.key`。SQLite 采用 WAL 模式；管理员密码经过 scrypt 处理；账户凭证使用独立随机 IV 的 AES-256-GCM 加密；会话令牌以哈希保存。

会话、自动关机规则、资源操作进度及操作日志均保存在数据库中。Docker 通过命名卷持久化 `/app/data`，数据库与加密密钥必须共同备份和恢复。

## 运行标识

npm 包、Compose 项目与服务、Docker 容器、hostname 和启动命令统一命名为 `lightsail-panel`。Dockerfile 清除继承的 entrypoint，`bin/lightsail-panel.mjs` 通过 shebang 运行 Node.js，应用作为容器 PID 1。`--healthcheck` 模式仅查询本地健康端点。

运行阶段通过 `NODE_OPTIONS=--max-semi-space-size=2` 调整 V8 年轻代空间，减少常驻内存及短时分配峰值。构建阶段保留 Node.js 默认设置。Compose 允许覆盖该变量；不设置较小的老年代上限或容器内存硬限制，资源缓存、采集并发、刷新周期与 SSH 会话策略保持原有语义。

`server/runtime-identity.mjs` 设置 `process.title` 与 Linux 线程的 `/proc/self/task/<tid>/comm`。启动时同步已有线程，1 秒后补充检查，之后每 30 秒修正新增或名称不同的线程。定时器使用 `unref`，服务停止时清理。该机制无需 root 或额外 capabilities；无法访问 `/proc` 时记录一次警告并继续运行。

Compose 数据卷标识与实际卷名均为 `lightsail-panel-data`，挂载到 `/app/data`。

## 扩展与验证

功能扩展须同步定义共享类型、参数校验、AWS 方法、HTTP 路由和前端模块。新增 AWS 命令须核对 IAM 策略并补充业务测试。

本地验证命令为 `pnpm check`、`pnpm test` 和 `pnpm build`。运行标识测试在独立子进程中验证进程标题、线程名称和健康检查退出码。Docker CI 在 amd64、arm64 上验证构建、启动命令、PID 1、线程名称、健康接口、初始化状态、前端资源、非 root 运行和 SIGTERM 退出；发布阶段验证 Compose 容器名称与数据卷挂载。
