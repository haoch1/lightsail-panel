# 架构说明

Lightsail Panel 由 React 前端与同源 Node.js 24 API 组成。服务端负责认证、输入校验、AWS 请求、凭证加密和数据持久化。

## 目录结构

| ----------------------------- | --------------------------------------------------- |

| `src/components/ui`           | 表单、下拉选择、弹窗、按钮和状态反馈                |

## 请求路径

`server/app.mjs` 在业务路由前执行来源校验、会话认证和 CSRF 校验。读取与修改资源的参数通过 Zod 校验后交给 `AwsGateway`。资源操作调用官方 Lightsail API，账户添加使用 STS 查询身份。

账户凭证仅在服务端解密，账户列表仅返回元数据与密钥尾号。默认 SSH 私钥下载须通过会话、来源和 CSRF 校验，响应禁止缓存。

账户记录保存 SDK 身份验证端点区域，资源查询区域由前端独立选择。

## SSH 终端

AWS 返回的 `expiresAt` 可选；存在时预检到期时间，证书有效期由 OpenSSH 在认证阶段校验。

实例操作菜单动态加载 xterm.js 与 FitAddon。终端测量容器独立于外层边框和内边距；ResizeObserver 同步终端与服务端 PTY 尺寸。全屏切换保留终端实例、输出和 WebSocket 连接。Escape、Tab、Ctrl+C 由终端处理；关闭窗口结束连接，断线保留输出，重连建立新会话。

历史滚动统一由 xterm 滚动组件处理，背景层禁用原生滚动。终端容器在捕获阶段拦截 `Ctrl+Shift+C` 并复制选中文本；无选区时保留剪贴板。

`POST /api/ssh/connect` 经会话、来源与 CSRF 校验后签发单次票据，绑定当前会话，有效期 45 秒。`/api/ssh/terminal` 校验 WebSocket 来源与登录 Cookie，票据通过第一帧提交并立即消费。连接与待用票据合计上限为每会话 4 个、全局 16 个。

`server/ssh/sessions.mjs` 确认实例运行后调用 `GetInstanceAccessDetails`，通过 `server/ssh/openssh.mjs` 启动 OpenSSH 和 node-pty。临时私钥、证书与 AWS 主机密钥记录写入受限临时目录，使用证书认证与严格主机密钥校验，禁用密码、代理、端口转发及用户 SSH 配置。子进程只继承运行所需的系统变量，不继承 AWS 或面板密钥。PTY 提供终端控制字符及远程窗口尺寸同步，登录 shell 发出就绪标记后才允许输入。

WebSocket 每 15 秒检查心跳、登录有效期和账户状态；退出登录立即撤销连接。超时、断线、关闭窗口或停止服务时结束 PTY 并清理临时文件。审计仅记录连接目标与结果，票据、终端输入输出和临时密钥不持久化。SSH 会话独立于资源缓存。Docker 构建阶段编译 node-pty，运行镜像内置 OpenSSH；反向代理须支持 WebSocket。

## 缓存与并发

`shared/refresh-policy.ts` 定义 5 分钟更新周期，按每小时 00、05、10、15 分等时间点调度。服务端 `ReadCache` 按规范化路径缓存响应，合并并发请求并短期缓存失败结果。手动刷新立即查询，跳过已完成的缓存。

前端跨页面共享资源缓存与在途请求，账户和区域扫描并发上限为 4。查询期间保留快照及行顺序，响应后原位更新；资源变更标记快照过期。连接失败保留上次结果，错误合并为可关闭提示，查询恢复后清除。

常规自动查询仅在页面可见时运行。服务重启清除内存查询缓存。

资源写操作按 `shared/resource-update.ts` 定义的账户、区域和资源类别使缓存失效。操作完成与异步状态变化通过应用级通知更新当前视图，其余缓存保持有效。

登录续期和自动关机规则保存不使资源缓存失效。规则检查与操作跟踪由服务端独立调度。

`server/launch-network.mjs` 将创建后网络配置与操作跟踪进度持久化至 SQLite。队列以 5–15 秒间隔和受限并发查询待完成操作，确认结果后结束，最长处理 10 分钟；新实例跟踪至运行状态。前端读取本地进度，页面刷新、切换或服务重启均复用任务记录。

资源写操作同时检查持久化待处理任务与进程内提交锁，阻止同一目标的并发请求。任务状态变更通过经认证的 `GET /api/events` SSE 连接通知前端，前端随后读取本地进度与对应资源；断线后自动重连，并保留轮询回退。完成提示显示 8 秒，失败提示保留错误详情并支持关闭。

`shared/firewall.ts` 将 AWS 协议编号规范化为 API 协议名称，统一创建、开放及状态确认的覆盖判断。协议、端口范围、IPv4、IPv6 与来源别名分别比较，CIDR 按网络地址及前缀匹配。已覆盖的开放请求不执行 AWS 写操作；关闭操作仅确认对应协议、范围与来源规则已移除，不将其他较宽规则误判为关闭失败。

## 界面布局

公共 `Modal` 采用固定标题与滚动内容区，尺寸受视口约束。流量视图保持加载、空数据和查询结果的布局一致，切换统计范围时保留上一结果。桌面明细使用表格及独立滚动区，不为未出现的滚动条预留空白；移动端将资源表格转换为带字段标签的信息卡片，流量明细保留日期、入站、出站及合计值。创建目录加载状态复用现有控件。

创建页沿用主内容区宽度与边距。操作菜单统一图标尺寸、行高及文字起始位置，并进行中文字符的光学居中校正。`PendingButton` 在提交期间保持文案、尺寸与焦点，采用 160 毫秒透明度过渡，并通过 `aria-busy` 和状态播报反馈进度。提交期间阻止重复操作、锁定输入与弹窗关闭，保留错误内容至请求返回。刷新按钮采用相同禁用样式，焦点恢复使用 `preventScroll`。

## 流量计算

流量使用 `GetInstanceMetricData`，指标为 `NetworkIn` 和 `NetworkOut`，统计方式为 `Sum`，单位为 `Bytes`。查询范围从浏览器时区的日期零点开始，到最近完成的 5 分钟区间结束。历史按小时汇总，首尾不足一小时的部分按 5 分钟查询，时间窗口互不重叠。

`shared/traffic.mjs` 负责时间窗口、重复点去除与按日汇总。本月、今日、近 7 天和近 30 天采用相同日期边界；缺失点和查询失败保持未知。数值仅在展示时格式化，流量保留两位小数。

流量展示统一使用 KB、MB、GB、TB，按 1024 换算；内部仍保存原始字节数，月额度与阈值计算保持一致。刷新及查询时间显示至分钟，审计事件时间保留秒。

`src/hooks/useInstanceUsage.ts` 共享区域套餐目录与本月流量缓存，按实例 `bundleId` 取得月额度。`TrafficProgress` 在列表和自动关机窗口展示用量、额度与比例。条形长度限制为 100%，百分比保留实际值；90% 和 100% 分别使用主题警示色与错误色，缺失数据标记为未知。

## 登录有效期与自动关机

登录有效期通过下拉框选择 12 小时、1 天、7 天、30 天或 90 天，默认 30 天；SQLite 会话过期时间与 HttpOnly Cookie 同步，续期只修改当前会话，不随普通请求自动延长。

`server/traffic-guard.mjs` 将实例阈值规则保存在 `traffic_limits` 表。规则默认关闭，阈值支持 0.1–100%，按区域套餐返回的流量额度与本月入站＋出站合计判断，月份使用规则保存的时区偏移。后台检查对齐每小时 00、05、10、15 分等时间点，最多两路并发；资源操作完成后立即检查对应实例，不依赖浏览器登录状态。规则绑定实例 ARN，替换同名实例须重新配置。

自动停止前再次确认实例状态和规则版本，持久化停止意图后提交操作；关闭或编辑规则会取消尚未提交的检查结果。权限失败暂停规则，数据不完整不停止；无法确认请求结果时不重复提交。停止请求通过资源队列跟踪实际状态并更新列表，结果写入操作日志。重启服务继续读取规则，下月不自动启动实例。

## 持久化

### 操作日志

`audit` 表保存操作标识、时间、目标、结果与错误详情，最多保留 5000 条；`GET /api/audit` 返回最近 200 条。`shared/audit-actions.ts` 集中定义中文显示名称，AWS、SSH、IPv6、IP 等专业术语保留英文。

异步 AWS 写操作区分 `submitted` 与最终 `success` / `failed`。日志写入或清理后，Store 发布仅含事件类型的通知，经同源、会话认证的 SSE 连接使日志缓存失效；连接不传输凭证、资源详情或日志内容。后台任务及 SSH 连接审计使用同一机制；连接关闭、会话撤销或 Store 关闭时移除订阅。反向代理须关闭事件流响应缓冲。

`DELETE /api/audit` 经会话、来源和 CSRF 校验后删除全部日志，并返回删除数量。清理仅作用于日志表及前端日志缓存，资源查询缓存保持有效。界面复用 `Modal` 和 `PendingButton` 进行确认与提交反馈；演示模式仅清理内存记录。

### 数据与加密

数据目录包含 `panel.sqlite` 与 `encryption.key`。SQLite 采用 WAL 模式；管理员密码经过 scrypt 处理；账户凭证使用独立随机 IV 的 AES-256-GCM 加密；会话令牌以哈希保存。

会话、自动关机规则、资源操作进度及操作日志均保存在数据库中。Docker 通过命名卷持久化 `/app/data`，数据库与加密密钥必须共同备份和恢复。

## 运行标识

npm 包、Compose 项目与服务、Docker 容器、hostname 和启动命令统一命名为 `lightsail-panel`。Dockerfile 清除继承的 entrypoint，`bin/lightsail-panel.mjs` 通过 shebang 运行 Node.js，应用作为容器 PID 1。`--healthcheck` 模式仅查询本地健康端点。

`server/runtime-identity.mjs` 设置 `process.title` 与 Linux 线程的 `/proc/self/task/<tid>/comm`。启动时同步已有线程，1 秒后补充检查，之后每 30 秒修正新增或名称不同的线程。定时器使用 `unref`，服务停止时清理。该机制无需 root 或额外 capabilities；无法访问 `/proc` 时记录一次警告并继续运行。

Compose 数据卷标识与实际卷名均为 `lightsail-panel-data`，挂载到 `/app/data`。

## 扩展与验证

功能扩展须同步定义共享类型、参数校验、AWS 方法、HTTP 路由和前端模块。新增 AWS 命令须核对 IAM 策略并补充业务测试。

本地验证命令为 `pnpm check`、`pnpm test` 和 `pnpm build`。运行标识测试在独立子进程中验证进程标题、线程名称和健康检查退出码。Docker CI 在 amd64、arm64 上验证构建、启动命令、PID 1、线程名称、健康接口、初始化状态、前端资源、非 root 运行和 SIGTERM 退出；发布阶段验证 Compose 容器名称与数据卷挂载。
