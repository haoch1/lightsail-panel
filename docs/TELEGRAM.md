# Telegram 通知

## 配置

1. 在 Telegram 通过 [BotFather](https://t.me/BotFather) 创建 Bot，取得 Bot Token。
2. 向 Bot 发送 `/start`；群组须先添加 Bot，频道须授予发送消息权限。
3. 在面板 **设置 → Telegram 通知** 填写 Bot Token、Chat ID，选择通知类型并启用通知。
4. 保存后点击 **测试通知**，在 **最近通知** 检查实际投递结果。测试使用已保存的配置；修改未保存时不可测试。

日报时间通过弹层分别选择小时、分钟，点击确定后回到设置表单，保存设置后生效。

Chat ID 支持用户或群组的数字 ID，以及 `@频道用户名`。API 地址默认为 `https://api.telegram.org`，可配置受信任的 HTTPS 反向代理地址，不支持 URL 内嵌凭证、查询参数或片段。服务端须能访问该地址；浏览器不直接连接 Telegram。发送遵循 [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)。

Bot Token 使用现有 AES-256-GCM 密钥加密保存，不返回浏览器，不进入通知队列、消息正文或操作日志。已配置 Token 留空时保留原值；替换时填写新值。需要移除 Token 时关闭通知，勾选 **清除已保存的 Token** 后保存。备份须同时保留数据库和 `encryption.key`。

## 通知类型

| 类型         | 触发条件                                                          |
| ------------ | ----------------------------------------------------------------- |
| 资源操作成功 | 实例、防火墙、静态 IP 等操作已确认完成；不在 AWS 仅受理请求时发送 |
| 资源操作失败 | 相应操作失败，或等待资源结果超时；消息包含失败详情                |
| 流量保护关机 | 已启用的自动关机规则达到阈值后，关机结果确认成功或失败            |
| 实例状态变化 | 后台实例查询检测到状态变化；首次采集及替换实例仅建立基线          |
| 公网 IP 变化 | 连续两次运行状态采集中，IPv4 或 IPv6 地址发生变化                 |
| 监控异常     | 实例或流量查询首次异常，或自动关机规则检查报错                    |
| 监控恢复     | 此前异常的实例或流量查询恢复成功                                  |
| 每日汇总     | 到达指定时区的日报时间后，汇总最近采集的实例状态和月度流量        |

通知默认关闭。默认勾选资源操作失败、流量保护关机、公网 IP 变化和每日汇总，其余类型可按需选择。实例状态、IP 变化与监控查询复用现有采集结果；Telegram 功能不增加 AWS API 调用，不需要额外 IAM 权限。

实例状态变化与资源操作结果是不同通知类型，全部勾选时同一次关机可能分别收到操作结果和状态变化消息，可按需要取消其中一类。SSH 终端内容、SSH 私钥、账户凭证与登录信息不发送。设置中不提供本项目未实现的保活、定时开关机、自动开机恢复或账单通知。

## 日报与投递

消息使用状态图标、加粗标题、引用正文和单一时间标记；资源标识显示地区国旗及实例名，不显示账户或区域代码。国旗按 AWS 地区映射，地区无法确认时省略。错误消息保留必要详情，监控恢复消息附“查询已恢复”。流量保护关机消息在数据可用时展示使用比例、已用与剩余流量；IP 变化只列出实际发生变化的地址。消息不附带计费声明、采集时间或时区说明。设置页预览与实际发送共用同一格式；资源名称和详情在发送前进行 HTML 转义。

默认日报时间为 `09:00`、时区为 `Asia/Shanghai`，标题为 `🟢 LightSail 实例日报 YYYY-MM-DD`，日期按配置时区确定。日报每个时区日期最多生成一次；服务恢复后，当天已过计划时间且尚未生成日报时补发当天汇总，不补发历史日报。使用 SQLite 中最近成功的快照，不另行查询 AWS；展示实例总数、运行与停止数量，以及最多 5 台实例的状态和本月流量，其余实例提示在面板查看。

日报每台实例使用独立段落，例如 `🇸🇬 Lightsail-SG · 运行`，下一行为 `本月流量 77.88 GB / 200.0 GB`。已用流量保留两位小数，套餐额度保留一位小数；额度按同一账户、地区及实例套餐匹配既有缓存，不使用其他实例或账户的额度。缺失的流量或额度显示待同步，过期月份的流量不沿用、不按零计算。流量统计沿用快照对应的查询周期，并非 AWS 计费流量。

后台发送独立于浏览器运行。队列持久化保存，服务重启后继续处理；网络或服务端临时错误最多尝试 5 次，普通重试间隔依次为 30 秒、60 秒、120 秒、240 秒。Telegram 返回 `429` 时遵循 `retry_after`，暂停该通道发送；无效 Token、接收权限等明确的客户端错误停止重试。测试消息至少间隔 10 秒。

最近通知列表仅显示消息标题，不显示正文或展开控件。成功记录的投递状态仅显示“已发送”；重试中或失败的状态保留尝试次数及错误详情。Telegram 实际消息仍包含完整正文。

修改 Token、Chat ID 或 API 地址后，旧接收配置的待发送消息取消，不转发到新目标；关闭通知或取消某种类型时，相应待发送消息跳过。排队超过 24 小时的消息过期。最多保留 500 条待发送消息及最近约 200 条投递结果，设置页展示最新 20 条。网络中断或服务在 Telegram 已接收消息后退出时，无法保证严格的恰好一次投递。

## 排查

- **未生成通知：** 检查总开关、保存状态及类型勾选。状态变化通知需要先有成功采集的基线。
- **等待发送：** 检查服务端网络、队列记录中的错误及重试状态；Telegram 限流时按服务器指定时间等待。
- **401 / 403：** 核对 Token，确认 Bot 未被用户屏蔽，并检查群组或频道发送权限。
- **400：** 核对 Chat ID、是否已发送 `/start`，以及目标会话是否仍可用。
- **日报流量缺失：** 等待既有后台采集完成。通知不主动扩大 AWS 查询范围或读取计费接口。
